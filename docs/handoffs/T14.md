## Files

| File | Why |
|---|---|
| `src/presentation/drag/drag.ts` | `DragController`: one active pointer, occupied-cell picks only (empty L padding cannot start a drag), 6 CSS px threshold, touch lift applied in CSS px and then converted with the same viewport mapping, snapped anchor `floor(lifted / pitch) − grabbed`. The preview runs the same domain `canPlace` that `placePiece` uses, plus `applyPlacement`/`resolveClears` on a copy for lines it would clear. Release recomputes from the release point and the current state/revision and submits one `PlacePiece`; invalid drops are never clamped. No DOM, so it's tested in Node |
| `src/adapters/pointer/pointer-adapter.ts` | The single Pointer Events path: `setPointerCapture` on claim, other pointers ignored until the active one ends. Cancels on `pointercancel`, `lostpointercapture`, window `blur`, hidden document, `resize` and `screen.orientation` change. Swallows the click that follows a drag (capture-phase listener on the canvas). Returns a disposer that removes every listener |
| `src/adapters/pixi/game-view.ts` | `showDrag(preview)`: hides the source tray slot, draws the floating piece at board pitch, the snapped ghost (shape color at `ghost_alpha`), accent outlines on every cell of lines the drop would clear, and for invalid spots an outline plus a cross in the `invalid` color (not color alone). The ghost is redrawn only when the anchor changes |
| `src/bootstrap/main.ts` | Holds one `GameSession`; an accepted command updates canvas and HUD. Game over shows plain status text (`shortcut:` until T18). Pointer listeners are disposed on teardown/retry |
| `tests/pointer/drag.test.ts` | 41 Node tests for the controller |
| `tests/browser/pointer.spec.ts` | Real mouse and CDP touch input against the production build |
| `tests/browser/helpers.ts` | Shared browser-test helpers, extracted from `layout.spec.ts` |
| `tests/unit/architecture.test.ts` | `src/presentation` now has the same purity rule as domain/application (no DOM, Pixi, clock, outer layers) |
| `vite.config.ts` | Vitest includes `tests/pointer` |

Node (`tests/pointer`): picks; second pointer ignored; game over; threshold and taps; a fast flick with no move events still counts at release. Ghost cells equal committed cells for 5 targets on all four board edges × 3 CSS box scales × mouse/touch. Touch lift moves the preview by exactly the converted CSS distance. No consumption for partly-off-board, outside-canvas, occupied, cancelled, or already-consumed pieces. Release uses the current revision. A preview reports the row it would clear and leaves the session untouched.

Browser (headless Chromium, SwiftShader; projects `root` and `nested`):
- **Ghost and commit coincide** with mouse at DPR 1/2/3 and touch at DPR 1/3. The first deal goes to the top-left, top-right and bottom-left corners, then the refill to bottom-right. Mid-drag, screen pixels on every placed cell match the ghost blend (`ghost_alpha` over `empty_cell`, ±6). The pointer is offset 0.45 pitch, so the floating piece doesn't hide the ghost. After release, all 100 board cells, the score and slot-button states match a Node copy of the same seeded session.
- **No stray outline:** with no line to clear, the edge of every ghost cell is not the accent color. This check failed on the first version (an empty `stroke()` re-stroked the last ghost tile) and passes after the fix.
- **Invalid spot:** cross pixels in the `invalid` color on every covered cell; release consumes nothing.
- **Cancels:** blur, hidden document (`document.hidden` overridden + `visibilitychange`), viewport resize, `screen.orientation` change event, pointer-capture loss, release outside the canvas, and touch `pointercancel` all consume nothing; the piece returns to the tray.
- **Second finger:** finger B is pressed on another tray piece and lifted over a legal board spot while finger A drags. Only A's piece is placed.
- **Clicks:** a valid drag and an invalid drag produce 0 clicks on the canvas; two plain taps produce 2.
- Screenshots: `docs/evidence/t14/ghost-valid-dpr{1,2,3}-*.png`, `ghost-invalid-*.png`.

## Decisions

- The ghost layer draws above the floating piece. The same-color translucent ghost leaves the piece unchanged, and the invalid cross and line outlines stay visible when the piece sits right on them (found from the first evidence screenshots, where the floating piece hid the cross).
- The lines-to-clear outline is covered by Node tests (`completedRows`/`completedColumns` in the preview) and not by a browser pixel test.
- A press on a tray piece that ends under the threshold is a tap. It does nothing yet; tap selection is T15. The click it produces is not suppressed.
- The ghost shows lines-to-clear with outlines rather than color changes.
