The tests cover the following:
- **Shipped content:** 19 unique, connected, normalized pieces, all of which fit the 10×10 board.
- **Invalid inputs:** 35 cases are rejected. They include unknown keys, out-of-range board/tray, non-integer/unsafe/non-finite values, and unsupported enums (rotation, undo, multiline bonus, policies, generator). Shape cases include duplicate IDs, repeated cells, empty, disconnected or diagonal shapes, negative or fractional coordinates, unnormalized shapes, zero weight, weight overflow, missing color key, a shape too big for the board, and a path escaping the release.
- **Loader failures:** 13 cases. They include network error, 404, HTML served for JSON, truncated JSON, stale manifest version, unknown runtime contract, catalog/manifest mismatch, missing or invalid theme color, a non-WebGL2 renderer, a rect outside the canvas, volume out of range, and a cross-origin track.
- **Hash:**
  - It stays the same for edits to color keys, provenance, `ruleset_id`, key order and cell order.
  - It changes when any of these change: score per line or per cell, board, tray, weight, catalog order, removing a shape, geometry, or a shape ID.
- **Browser:** a 404 index shows a precise error with Retry, and Retry recovers. Hosted rules with `tray_size: 9` are rejected before any canvas exists.

## Decisions

- **Shape IDs are in the hash** because saved boards and trays reference them.
- **Excluded from the hash:** `ruleset_id`, `catalog_id`, `provenance`, `color_key`, `schema_version` and file paths.
- **Board tiles store shape IDs.** The theme maps shape → color key → color, so cosmetic releases never touch saves.
- **Presentation files are strict too.** Unknown keys in theme, runtime and audio files are rejected to catch typos.
