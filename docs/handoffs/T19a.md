What the dark-mode spec checks (Chromium, `root` and `nested`):
- **Mid-run switch:** place a piece, then pause and pick Dark in Settings.
  - `data-theme="dark"`, `color-scheme: dark`, and the dialog background is `rgb(27, 36, 38)`.
  - After Resume, screen pixels show the canvas background and an empty cell in the dark colors, while the placed tile keeps its color.
  - Score, tray slot labels and Saved are unchanged. After a reload the page is still dark and Continue restores the same score.
  - Screenshots: `settings-dark-*.png`, `board-dark-*.png`.
- **Match my device:** with the device in dark mode, the default setting shows dark. Switching the device to light changes the page and board to light without a reload.
- **Override:** choosing Light on a dark device shows light.

Two first-run failures were in the tests, not the app: sampling right after Resume read the last frame drawn before the pause, and sampling on the first-load menu read through the dialog backdrop. The tests now wait for a fresh frame and start straight into a run.

## Decisions

- One `dark` block inside `theme.json` instead of a second theme file. Only five colors differ, timings and tile colors are shared, and the manifest and loader stay unchanged. T21 can restructure themes when it adds the high-contrast canvas palette.
- The default theme is "Match my device". Saves that already store `light` or `high_contrast` keep them.
- Release `1.1.0` content was edited in place: it has not been published, and theme data is excluded from the gameplay hash. Once content is hosted, a theme change needs a new content version.
