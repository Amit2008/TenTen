## Files

| File | Why |
|---|---|
| `src/presentation/input_modes/selection.ts` | `SelectionController`: selected tray instance + anchor (the board cell for the shape's local (0,0)). Keys `1`–traySize select, arrows move the anchor with the bounding box kept on the board, Enter/Space commit (repeats ignored), Escape clears. A tap on a tray slot (anywhere in its rect, including empty L padding) selects or deselects it; a board tap puts the anchor on the tapped cell (not clamped) and commits if legal. `key()` returns whether the key was used. `refresh()` clears a consumed or stale selection after each move. No DOM |
| `src/presentation/views/preview.ts` | `placementPreview()`: the single read-only placement query (domain `canPlace`, plus `applyPlacement`/`resolveClears` on a copy) shared by drag and selection |
| `src/presentation/drag/drag.ts` | Uses `placementPreview`. Every press while the run is active is claimed; one that stays under the threshold is reported as a tap (logical point), so taps stay on the single Pointer Events path instead of `click`. Only presses on occupied tray cells can become drags. `cancel()` emits a cleared preview only if a drag had started, so a tap never wipes the selection ghost |
| `src/adapters/dom/keyboard.ts` | `keydown` on the canvas only (`tabindex=0`, `role="application"` with a label that lists the keys). Ctrl/Meta/Alt chords are never puzzle keys; `preventDefault` only when the controller used the key. Outside `src/presentation/input_modes`, but the DOM listener belongs in an adapter |
| `src/adapters/dom/hud.ts` | Slot buttons select their slot and expose `aria-pressed` |
| `src/adapters/pixi/game-view.ts` | `showSelection()`: tray-slot highlight, the ghost, and a ring on the anchor cell, which shows even when that shape cell is empty |
| `src/bootstrap/main.ts` | One `commit` path for all input modes; a slot-button click focuses the canvas; a drag clears any selection |
| `src/bootstrap/shell.css` | Selected button: filled with a heavier border (not color alone); canvas `:focus-visible` outline |
| `tests/input_modes/selection.test.ts`, `tests/browser/input-modes.spec.ts` | Acceptance tests |
| `tests/pointer/drag.test.ts` | Updated for tap claiming, plus a tap test |

What the tests prove:
- **Same cells in every mode:** with `corner_3_2` (empty local origin) at anchors (0,0), (7,7) and (4,2):
  - Node: keyboard, tap and drag commit the same anchor and the same board.
  - Browser (seed 1): mouse (slot button + board click), CDP touch taps (tray piece + board cell) and keyboard (Tab, `1`, arrows, Enter) each give all 100 board cells and the score equal to a Node copy of the session. The origin cell stays empty.
- **Anchor marker:** the ring pixel at the anchor cell is the theme `text` color during keyboard selection at (0,0) (`docs/evidence/t15/keyboard-anchor-*.png`).
- **No double commit:** a held Enter (`repeat=true`) does not commit. Node also covers held Space, and Enter on an illegal anchor (no commit, selection kept).
- **Browser keeps its keys** (a 300 px tall page that scrolls): with nothing selected, ArrowDown and Escape are not prevented, and the page actually scrolls. Ctrl+1 and `4` (beyond the tray) are not prevented. With a selection, `1`, ArrowDown and Escape are prevented. Tab moves focus from the canvas to slot button 1, and arrows on a focused button are not prevented.
- **Drag and selection together:** a slot button focuses the canvas; starting a drag clears the selection and the drop still commits.

## Decisions

- The anchor persists across selections and after a commit. The first selection starts centered. Keyboard moves keep the bounding box on the board; taps do not clamp (an off-board box shows as invalid).
- A tap anywhere in a tray slot's rectangle selects it, which is easier than hitting small tiles. Drags still require an occupied cell.
- Escape with nothing selected is left unhandled for the pause screen (T16).
- A mouse tap on the canvas does not move focus to it (`pointerdown` default is prevented); keyboard players reach it with Tab or a slot button.
