Frame-rate traces from six runs: four in the repeat run and two in the full suite, `root` and `nested`. All 19 per-move hashes matched Node in every run, and the final hash was `68b46764c04b0ff9` each time:

| Requested | Measured rAF/s, repeat run | Measured rAF/s, full suite |
|---|---|---|
| 30 | 30–31 | 30–31 |
| 60 | 50–62 | 49–58 |
| 144 | 78–99 (115 on an idle machine) | 63–67 |

**The 144 fps run does not reach 144 frames a second** in headless Chromium on this machine. The frame clock is a timer, and the browser cannot deliver one every 6.9 ms while three workers run. In the full suite it was barely faster than the 60 fps run. So acceptance check 1 is shown for 30 against about 60–115 frames a second, not for a true 144. The 30 fps run is capped at 30. The test asserts a 1.2× upper bound and a loose lower bound, and logs the actual rate.

First-run failures that were in the new tests, not the app:
- The frame counter counted every callback instead of frames. It now batches callbacks per frame, as real rAF does.
- The hash included the content hash, which the Node mirror stubs. It now leaves out both identity fields, `sessionId` and `gameplayHash`.
- The scroll check expected `scrollY` 0, but focusing the board at the start had already scrolled it into view (12 px). It now compares before and after the swipe.
- The orientation test used anchors that are not legal for seed 1. It now uses the corner anchors proven by the corner test.

A first full run with default workers had 20 failures, nearly all pages still "Loading…" after 5 s. This is the machine-load pattern recorded in T19, and the evidence runs use `--workers=3`.

## Decisions

- The trace compares stored state (IndexedDB `current.active`) instead of screen pixels. It is the logical state that a refresh would restore, so a frame-rate effect on saves would show up too.
- Rapid commits are not part of the frame-rate trace. Whether a command lands inside the resolving window depends on timing, so it cannot give identical traces by design. The refusal itself is covered by `states.spec.ts`.
