## Files

| File | Why |
|---|---|
| `src/adapters/audio/web-audio.ts` | `WebAudioOutput`: the AudioOutput adapter. Master, music and effects gains. Music streams through one reused `Audio` element routed into the graph; effects are fetched and decoded into buffers once. Nothing is created or fetched before `unlock()`. | `src/bootstrap/main.ts` | Creates the adapter per load and destroys it on teardown. **Gestures:** only clicks on Continue, New game, Start new game, Play again, Resume and Enable sound call `unlock()`. **Suspend:** on pause (button, Escape, blur, hidden tab) and on any hidden tab, the menu included. **Effects:** pick (a drag starts or a slot is selected), place or clear (accepted move), game_over, invalid (a drag released over an invalid spot). Volume settings apply live |
| `index.html`, `src/bootstrap/shell.css` | Enable sound button (original speaker icon, left of the score), shown only while the browser refuses to start sound. It is inert while paused. How to play explains it |

What `audio.spec.ts` checks (Chromium, `root` and `nested`). The fixtures are sine-tone WAVs generated in the test and served by route interception, and `audio.json` is replaced for the test. They are not final assets.
- **Empty config** (audio.json with no tracks or effects): after New game and a move, no AudioContext was ever constructed, and no Enable sound button is shown.
- **Shipped effects:** New game fetches the five WAVs, and a move then plays pick (0.07 s) and place (0.14 s), told apart by buffer length.
- **Decoding across engines** (`sounds.spec.ts`): every shipped effect decodes with the expected length in Chromium (`root`, `nested`) and Playwright's Firefox. Playwright's WebKit build on Windows has no Web Audio at all (`AudioContext` is undefined), so it is skipped and recorded below.
- **Gesture gate:** before any click, no context exists and nothing has played. New game creates a running context, the first track plays, and the effect files are fetched. A move plays the pick and place effects.
- **Autoplay refusal** (context resume and media play rejected with `NotAllowedError`): New game and a move still work. Enable sound appears. Once the browser allows it, clicking Enable sound hides the button and starts the music.
- **Absent and bad assets** (a 404 track, a non-audio track, a 404 effect, an undecodable effect): each track is tried exactly once, with no further attempts a second later. Four warnings are logged, the move plays with no effect, and no Enable sound button appears.
- **Pause, hidden tab, rapid restart:** Pause suspends the context and Resume runs it again. A hidden tab suspends it, and Resume after return runs it. Then three quick Restart → Start new game cycles. Every play call was for the first 8 s track; the playlist never advanced.
- **Track end and volume:** 0.3 s tracks play 1, 2, 1 (repeat). Gains start at the content defaults (70/30/70), and moving Master to 0 and Music to 55 in Settings sets them to 0 and 55.

Defect found while writing the tests and fixed: decoded effects were discarded because their stale-load check used the track generation, which the first track bumps. The check is now "the context is still the live one".

Test fixes, not app defects: the 0.3 s tracks keep advancing while the test polls, so it compares the first three entries. Keyboard placement waits for the board to have focus.

## Decisions

- **Gesture list, not any click:** the GDD names Play, Resume and Enable sound gestures, so slot buttons and board taps never start audio.
- **Enable sound only when refused:** the button appears after a refused start, not before the first gesture. New game or Continue is itself the gesture in the normal case.
- **Pause resumes the same track:** a paused or suspended track continues where it stopped. Only `ended` (checked against the track's generation and the suspended flag) advances the playlist.
- **No mute toggle:** Master volume 0 in Settings is the mute. The GDD's "button icon for audio" is the Enable sound button.
