## Bug fixed (found by Amit while testing T23)

The tray could show the previous game's pieces after New game, Restart or Play again in the same page load. `GameView` redrew a slot only when its piece instance number changed, and every run numbers its pieces from the start, so the new run's pieces 0–2 looked unchanged. Slots are now keyed by session id plus instance (`game-view.ts`). The bug had been there since T18. A repro script showed the canvas tray matching the slot labels across three restarts after the fix (it did not before).

## Accessibility checklist

| Item | State |
|---|---|
| Reduced motion | Setting (Follow device / Reduce / Full) from T19, stored. Reduced: no pulse (an opacity cue instead), no glide; every state change still happens |
| Focus visibility | 3 px accent ring on every control and the board (`:focus-visible`), all themes |
| Target sizes | Every button at least 44×44 CSS px (slots, pause, sound, menus, dialogs, radios' rows) |
| Touch comfort | Piece floats 36 CSS px above the finger; 6 px drag threshold |
| Contrast | T21 tables; High contrast for strict needs |
| Not by color alone | Invalid: outline + cross; lines to clear: outline; selection: frame + anchor ring + pressed slot button |
